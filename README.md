# WhatsApp Chat · GREEN-API

Веб-интерфейс для отправки и получения текстовых сообщений в WhatsApp через [GREEN-API](https://green-api.com/). Внешний вид повторяет [web.whatsapp.com](https://web.whatsapp.com/).

## Возможности

- вход по `idInstance` и `apiTokenInstance` с проверкой состояния инстанса;
- создание чата по номеру телефона получателя;
- отправка текстовых сообщений ([SendMessage](https://green-api.com/docs/api/sending/SendMessage/));
- получение ответов через HTTP API ([ReceiveNotification / DeleteNotification](https://green-api.com/docs/api/receiving/technology-http-api/));
- сохранение сессии и истории после перезагрузки страницы;
- светлая и тёмная темы (по настройке системы) и адаптивная вёрстка.

## Локальный запуск

Нужен Node.js 20.19 или новее (в CI используется версия из `.nvmrc`).

```bash
npm ci
npm run dev
```

Приложение откроется на http://localhost:5173.

Production-сборка и её предпросмотр:

```bash
npm run build
npm run preview
```

## Подготовка инстанса GREEN-API

1. В [личном кабинете](https://console.green-api.com) создайте инстанс WhatsApp и авторизуйте его: отсканируйте QR-код в WhatsApp (Связанные устройства → Привязка устройства).
2. Скопируйте `idInstance` и `apiTokenInstance`.
3. В настройках инстанса оставьте поле `webhookUrl` пустым и включите получение входящих сообщений (`incomingWebhook: yes`). Без этого ответы не попадут в очередь HTTP API.
4. Режим `EnableLidMode` должен быть выключен (по умолчанию так и есть): приложение адресует чаты по номеру телефона (`79991234567@c.us`).

## Как пользоваться

1. Введите `idInstance` и `apiTokenInstance`.
2. Укажите номер получателя в международном формате (`79991234567`, `+7 999 123-45-67` или `8 999 123-45-67`) и нажмите «+».
3. Напишите сообщение и отправьте его клавишей Enter (перенос строки — Shift+Enter).
4. Ответ получателя из WhatsApp появится в чате автоматически.

## Архитектура

Проект построен по [Feature-Sliced Design](https://feature-sliced.design/). Слой может импортировать только нижележащие слои, а слайс доступен снаружи только через свой `index.ts`. Соблюдение правил проверяет Steiger.

```
src/
├── app/                  точка входа, провайдеры, глобальные стили и дизайн-токены
├── pages/
│   ├── login/            страница входа
│   └── messenger/        список чатов + окно чата, запуск получения сообщений
├── widgets/
│   ├── chat-sidebar/     список чатов, сортировка по последней активности
│   └── chat-window/      шапка, лента сообщений, поле ввода
├── features/
│   ├── auth/             вход (GetStateInstance) и выход
│   ├── create-chat/      проверка номера (CheckWhatsapp) и открытие чата
│   ├── send-message/     отправка сообщения (SendMessage)
│   └── receive-messages/ очередь уведомлений (ReceiveNotification → DeleteNotification)
├── entities/
│   ├── session/          учётные данные инстанса
│   ├── chat/             чаты: стор, заголовок, элемент списка
│   └── message/          сообщения: стор, «пузырь» сообщения
└── shared/
    ├── api/              HTTP-клиент и методы GREEN-API, типы, работа с chatId
    ├── config/           общие константы
    ├── lib/              утилиты: телефон, даты, ошибки
    └── ui/               UI-кит: Button, Input, Avatar, ErrorMessage, иконки
```

Константы, которые относятся к одному слайсу (тексты ошибок, задержки), лежат в его сегменте `config`.

## Как это работает

**Адрес API.** Запросы идут напрямую из браузера (GREEN-API разрешает CORS) на `https://{первые 4 цифры idInstance}.api.green-api.com/waInstance{idInstance}/{method}/{apiTokenInstance}`.

**Вход.** Учётные данные проверяются методом `GetStateInstance`. Войти можно только в инстанс со статусом `authorized`, для остальных статусов показывается понятная причина.

**Создание чата.** Номер нормализуется и проверяется, из него строится `chatId` вида `79991234567@c.us`. Метод `CheckWhatsapp` подтверждает, что у номера есть WhatsApp, и возвращает номер в каноническом виде. Для уже открытого чата `CheckWhatsapp` повторно не вызывается: так экономятся лимиты метода.

**Отправка.** `SendMessage` с `chatId` и текстом (до 20000 символов). Сообщение попадает в ленту после ответа сервера с `idMessage`. При ошибке текст остаётся в поле ввода.

**Получение.** Пока открыт мессенджер, работает цикл long polling:

1. `ReceiveNotification` с `receiveTimeout=20` ждёт уведомление до 20 секунд;
2. уведомление обрабатывается: в ленту попадают входящие текстовые сообщения, в том числе ответы с цитатой; для нового собеседника создаётся чат;
3. `DeleteNotification` удаляет уведомление из очереди. Удаляются уведомления любого типа, иначе очередь остановится.

Уведомление удаляется только после обработки, поэтому при сбое оно придёт повторно. Сообщения дедуплицируются по `idMessage`, и повторная доставка не создаёт дублей. При сетевой ошибке опрос возобновляется через 5 секунд.

**Хранение.** Сессия, чаты и история лежат в `localStorage` и очищаются при выходе.

## Деплой

Workflow `.github/workflows/ci.yml` на каждый push и pull request запускает линтеры, тесты и сборку. При push в `main` он публикует сборку на GitHub Pages. Для этого в настройках репозитория выберите **Settings → Pages → Source: GitHub Actions**.

Сборка использует относительные пути (`base: './'`), поэтому содержимое `dist` можно разместить на любом статическом хостинге.

## Ограничения

- Бэкенда нет: `apiTokenInstance` хранится в `localStorage` браузера пользователя.
- Очередь уведомлений у инстанса одна, поэтому одновременно должна быть открыта одна вкладка: несколько вкладок будут забирать уведомления друг у друга.
- История начинается с момента входа. Загрузка прошлой переписки (`GetChatHistory`) не входила в минимальный набор функций.
- При включённом `EnableLidMode` входящие приходят с `chatId` вида `…@lid` и не сопоставятся с чатами, созданными по номеру.
